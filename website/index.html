WHAT RIG OS DOES

Models propose.
You keep control.

A browser console and an authenticated service run on your computer. The runtime keeps proposals, permissions, input receipts, and verified results separate.

[01]

Choose the models

Use Ollama, Codex CLI, or Claude CLI. Choose ordered fallback or compare proposals from several models. External providers require explicit consent.

Provider setup →
[02]

Bound the action

Review desktop input. Pin versions, restrict targets, set deadlines, and pause or take over. Uncertain input is not automatically replayed.

How execution works →
[03]

Inspect the result

Save run evidence, compile recordings into tested skills, and create checked JSON or CSV artifacts. An input receipt alone does not prove success.

Explore the workflows →

WHY MAP A SYSTEM?

The code keeps moving.
Keep the explanation close.

As a system grows, its behavior spreads across files. A map helps you see who owns a decision, where data moves, and what a change might affect.

Here, each traced responsibility leads back to source. Journeys make the handoffs visible. Source fingerprints and reviewed update records help catch stale documentation. Reading the changed behavior still matters.
