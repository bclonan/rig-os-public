# Wayland portal profile

The worker implements XDG RemoteDesktop with ScreenCast on the same session. It uses the selected monitor's authorized PipeWire descriptor and node. It never substitutes XWayland input or a default PipeWire node. Service startup does not request permission. `npx tsx scripts/desktop.ts consent` opens the real permission dialog explicitly, checks the result, and closes that diagnostic session. The service's consent API retains its own session.

`capabilities.consent` reports `required`, `granted`, `pending`, `devices`, and the stream count. Operations and keys reflect the actual device grant. A capture-only grant exposes no global input. Session.Closed, portal/backend owner loss, or capture ERROR/EOS withdraw the grant and invalidate the observation. Pending Request.Close, takeover, stop, and parent EOF settle consent locally even though Request.Close produces no Response.

The current coordinate profile requires one selected monitor and a focused fullscreen target with matching monitor bounds, pixel dimensions, and scale 1. Generic floating-window origins and fractional scaling remain denied. GTK Wayland can report a fabricated origin for parentless windows, so an in-bounds crop alone does not authorize the target. This is a deliberate limit on the implemented mapping, not an external dependency claim.

## Pixel provenance and static desktops

Mutter's monitor producer records after stage paints. It can remain silent on static content. Silence does not prove that the cached pixels still describe the current screen. Its producer can also skip a paint when no PipeWire buffer is available. These behaviors come from the installed version's upstream [monitor producer](https://raw.githubusercontent.com/GNOME/mutter/43.8/src/backends/meta-screen-cast-monitor-stream-src.c) and [stream recorder](https://raw.githubusercontent.com/GNOME/mutter/43.8/src/backends/meta-screen-cast-stream-src.c).

The capture pipeline disables keepalive, resend-last, and timestamp replacement. PipeWire's [GStreamer source](https://raw.githubusercontent.com/PipeWire/pipewire/0.3.65/src/gst/gstpipewiresrc.c) explicitly resends old buffers with updated timestamps when those options are enabled. The worker drains the newest queued sample within a bound and retains the source PTS. It maps PTS through the pipeline clock to `pixelCapturedAt`, records `pixelReceivedAt` separately, and increments `pixelFrameSequence` only when it receives a buffer. A cached display frame preserves all three values and sets `pixelFrameCached=true`.

Every consent session has a new `pipewireSessionGeneration`. Capture error, EOS, close, and consent withdrawal clear the cache and generation. The observation's `at` describes the fresh accessibility/session checkpoint. It is not the cached image's capture time. The TypeScript frame consumer must use `pixelCapturedAt` for these images and must not grant visual completion from cached or untimestamped pixels.

Global input preflight requires a new source-timestamped frame produced after the action's prior observation checkpoint. It waits at most 250 ms for that delivery and compares the current target, controls, frame, and pixels before dispatch. A static stream yields an action-bound `phase=rejected`, `dispatched=false` result and preserves consent. AT-SPI semantic actions remain available. Backend errors after execution starts stay uncertain.

Attempted key or button downs remain owned even when the reply is lost. Cleanup removes an owned release only after its call completes. Failed cleanup retains the input lock and manual quarantine until a successful retry or confirmed session closure. Quartz completion means that CGEventPost returned. It does not prove a macOS app effect.

## Native evidence

The current report is `evidence/linux-portal-v1/mutter16/native-report-attempt16.json`. It passes 20 checks on a disposable private D-Bus session with Mutter 43.8, GNOME portal 43.1, frontend portal 1.16, PipeWire 0.3.65 and its GStreamer plugin 0.3.65. The plugin version is separate from GStreamer core. Its source hashes bind the four Linux worker modules and the three live evaluation files. The real dialog trees, selected monitor image, compositor/portal logs, and independent GTK callback state accompany the report.

The fixture is fullscreen on one 1280 by 900 virtual monitor at scale 1. It repaints the same canvas pixels every 40 ms to provide actual compositor frames. The evaluator pauses repainting for the static-frame negative check. That check proves preserved pixel timestamps and sequence, zero marker clicks, a typed preflight rejection, and retained actual consent. It then resumes repainting and verifies actual click, keyboard, drag, scroll, and hold/release effects through GTK callbacks. Three safe no-dispatch reobservations appear in the report. Each retry requires an exact bound typed rejection. A thrown RPC error never triggers a retry.

Headless Mutter initially had no keyboard seat. A separately consented setup session sends Escape and the owned fixture presents itself. The report records this setup separately. All claimed worker effects use the worker's own consent session. The evaluator also exercises actual Cancel, capture-only consent, backend and frontend owner loss, Request.Close, takeover, parent EOF, and incoming Session.Closed. A graceful shutdown of the task-owned PipeWire core causes the last signal. Calling Session.Close directly does not test an unsolicited Closed signal, as the [frontend source](https://raw.githubusercontent.com/flatpak/xdg-desktop-portal/1.16.0/src/session.c) shows.

Earlier failures remain in the evidence directory. Attempts 1 through 8 exposed test setup, target focus, asynchronous effect checks, owner-loss handling, and signal-trigger errors. Attempt 9 passed the earlier 19-check profile before the later safety repairs. Attempts 10 through 12 exposed static-stream timeout behavior after fresh preflight. Attempt 13 passed the new static negative but denied the first global input. Attempt 14 passed click and exposed noncanonical AT-SPI selection ranges. Attempt 15 follows the bounded fresh-buffer wait and canonical offset-range repair. Attempt 16 also enforces typed retry receipts. The initial GNOME Shell attempt failed on the container's missing login service. The successful backend is Mutter, not GNOME Shell.

`tests/portal_test.py` contains 18 protocol and fault checks. The existing nine Unix worker assertions also pass. Those doubles cover request races, denied grants, stale content, incoherent observations, exact receipt binding, lost down replies, failed release quarantine, and source-time cache handling. They are not native execution evidence. There is no native macOS or generic Wayland compositor claim here.

## Reproduction

The disposable image uses distro `/usr/bin/python3`, GI/AT-SPI, GTK 3 and 4, PIL, GStreamer, PipeWire, WirePlumber, Mesa software rendering, Mutter, and the GNOME portal backend. Start a private system D-Bus in the container when required by its installed backend. Enable toolkit accessibility only inside that disposable environment. Set `GTK_A11Y=atspi` in both the launch and private D-Bus activation environments. `evaluation/linux-portal-session.sh` records the session address and launches the compositor, audio/video services, portals, and owned fixture.

Use a new `XDG_RUNTIME_DIR` and `EVIDENCE_DIR` for each compositor session. Run the evaluation with `REPORT_NAME` set to a new filename so a failure is preserved. `INITIALIZE_OWNED_VIRTUAL_SEAT=1` performs the separately recorded real-consent setup on a headless environment without a keyboard. Copy every report and log before stopping the disposable container. The evaluation deliberately shuts down its own PipeWire core at the end, so restart a fresh session before another full run.
