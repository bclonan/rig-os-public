The service listens on loopback, requires a locally generated bearer token for API calls, checks Host and Origin, limits request bodies and sets a restrictive content policy. POST requests require correlation and idempotency identifiers. Successful mutations have durable response deduplication. A conflicting payload under an existing key is rejected.

Generated contracts cannot enlarge the caller's effect scopes. Every action binds run, requester, host, session, target, observation, frame, deadline and lease generation. Imported skills enter quarantine. Dataset imports verify schemas and content hashes, and discard imported claims of positive labels. The restricted adapters do not expose shell execution, uploads or messages.

Explicit skill migration supports only the known raw version 1 capsule to version 2 package route. It preserves exact original bytes, root and full transitive dependency hashes, and immutable migration/import receipts. Unknown fields, versions and transforms fail before installation. A foreign implementation hash is provenance only; the local validator recomputes the known transform. Import clears claimed tests/demonstrations and preserves uncertainty reasons. Positive trials cannot resolve those reasons by themselves. Publication rechecks the exact candidate and current dependency closure; altered dependencies or erased uncertainty require a new reviewed import and tests.

The Windows backend uses a named mutex. Only the owner releases held input during cleanup. Typing and drag segments are bounded and check focus. Oculix is private stdio and currently advertises capture only. Its pinned input tools cannot bind the target and lease at dispatch, so guarded native input executes those actions. Its broader tool catalog is not exposed. UIA operates on the selected window or an owned dialog.

The macOS and Linux workers use private stdio and a user-owned session lock with `flock`. They bind the window and process, compare current controls/content with the prior observation before input, and reject expired observations. Bound AX/AT-SPI invoke and fill can run without global focus; global pointer and keyboard input require it. Secure text controls are excluded. Mac screenshots need Screen Recording permission and input needs Accessibility permission. Quartz posting completion does not prove an app effect, and no native Mac execution is certified here. OS launchers accept a fixed app ID, never a model-provided executable or shell string.

Wayland starts without portal capture or global input. An explicit RemoteDesktop request obtains user consent and shares its session with ScreenCast. Only the granted devices and selected PipeWire descriptor/node become usable. Session loss, backend/portal owner loss and stream ERROR/EOS revoke that authority. Request cancellation settles locally even if Request.Close emits no Response. No XWayland or unrelated PipeWire stream bypass exists. Floating-window and fractional-scale coordinates remain denied. Cached source frames keep their original timestamps and cannot authorize current pixel input or visual completion.

An uncertain dispatch is journaled and cannot automatically retry. A failed follow-up capture does not imply the input failed. Typed host rejection must bind the exact action/run and explicitly prove `dispatched:false`; an arbitrary error is not a safe-retry receipt. An approved capsule may declare `fresh_observation` recovery within its frozen retry budget. The schema permits up to five retries; drawing capsules declare three. Each retry preserves the frozen arguments, obtains a new observation/action ID, repeats policy checks and spends durable retry and step budgets. Stop and takeover wait for the bounded segment and attempt owned input cleanup. Failed release retains ownership and quarantine until cleanup succeeds or a confirmed portal session closure withdraws its authority. Attempted downs remain owned even after a lost reply. Cleanup failure prevents `succeeded`. These controls cannot undo a click or save. Native takeover is not a hardware emergency switch. A client outside the ownership protocol can still interfere.

The API has one local principal and no multi-tenant authorization system. Data is not encrypted at rest. Native accessibility can expose ordinary document text in the authorized window; password controls are skipped. Untrusted native skills need review beyond schema validation. The bounded export redaction below is not a general detector for every possible secret in arbitrary artifacts. A semantic model's response never grants permission or objective completion authority.

The release excludes live service tokens, runtime databases, downloaded local models, private raw desktop captures, window inventories, file dialogs and diagnostic stores. It includes allowlisted controlled browser and portal fixture evidence. Native and completion results enter the archive only as a metadata summary with local paths, hashes and measured statuses. That summary is not a completion certificate. Original private evidence stays local and unchanged.

Remote access requires an explicitly configured authenticated tunnel or transport boundary. No script creates public listeners, firewall rules, credentials, certificate trust exceptions or OS policy changes. Secure desktops stay outside the supported control path. Only an explicit request opens the platform's own portal consent dialog; the model cannot grant that permission.

## Service controls

Cleanup failures persist against the affected host and session in the ExperienceStore. They block preparation and input for new tasks in that session. Restart marks interrupted tasks for reconciliation and requires explicit Return before the coordinator clears a cleanup barrier. The operator must inspect and release any still-held input first. A replacement worker cannot prove what its predecessor left held. Return preserves task state and cannot replay an interrupted cursor or resolve an unknown app effect. This barrier does not coordinate separate stores.

Input cleanup attempts every owned workspace, browser and guarded worker before reporting the collected errors. Shutdown and takeover also attempt capture-backend closure. Forced worker termination remains a cleanup failure. A rejected Return retains the session barrier. Successful Return clears only the adapter's acknowledged host and session scopes.

Status and shutdown routes require the same local bearer authentication as tasks. The CLI checks both the process ID and store identity before sending a shutdown request. Shutdown never discovers and kills arbitrary Node processes. A token is displayed or copied only through an explicit local command. The console stores it in session storage for the current tab and clears it on Disconnect. The default legacy token path remains available; custom stores use separate token files.

## Reviewed desktop tasks

The desktop planner can read the selected window's accessibility text and screenshot. Computer scope also supplies the supported window titles, executable names and app launcher list. It reads another app's controls only after a reviewed switch or launch. Ollama runs on loopback. Store contents can contain document text, screenshots and model proposals; `.data` stays out of Git and release archives.

General desktop input requires a matching approved proposal ID. A separately reviewed drawing program freezes all segments and canvas bounds before execution. The coordinator checks process, current controls, window frame and focus before input. Changed state invalidates approval. In computer scope, the model can select an observed handle/PID identity or a fixed launcher app ID. It cannot supply a program path, launch arguments, permission scope or host. Single-window scope rejects app navigation. Cached plan steps rebind named controls to fresh observations; coordinate input still requires fresh planning.

A reviewed action can still be wrong. Confirm the actual target and text shown in the console. Process exclusions are a usability boundary, not a sandbox for hostile applications. The assistant does not independently verify arbitrary free-form goals and records model completion and user confirmation separately from verified skill success.

## Local models and opinion caching

Language and vision providers require an HTTP loopback endpoint without credentials, query or fragment and reject redirects. The Ollama language and vision providers inspect model metadata before sending private prompts or images. They reject advertised cloud/remote models and missing completion/vision capability. The generic local endpoint provider does not perform that Ollama-specific metadata check. Its configured daemon must be trusted to keep requests local. A loopback URL alone does not prove that a provider is local.

The built-in HTTP service uses Ollama at `http://127.0.0.1:11434`. The console selects an installed model; it does not configure a remote endpoint or download weights. Trusted library callers can pass a different loopback endpoint to `OllamaProvider` or `LocalEndpointProvider`. There is no built-in HTTP setting for a generic endpoint. Both language providers advertise a 4,096-token limit and send that limit in the request. A server can still ignore it. Request cancellation and a 120-second transport timeout bound the local request, not the correctness of its answer.

Windows scoped semantic caching binds the model, detector, requested subject, exact image/canvas source and observation dependencies. Focus, target, frame, relevant events, stream gaps and overlapping changed regions invalidate reuse. A cache hit retains the original evaluation time and source observation ID. It is knowledge about those bytes, not fresh completion evidence, and cannot authorize input. Unix continues full target refresh and does not infer unchanged pixels from event silence.

## Owned-model training and activation

New stores use the deterministic `fixed` selector until an explicit activation succeeds. Training writes candidate checkpoints, reports and ONNX files. It does not register or activate newly trained weights. Recorded-experience training writes an explicitly unredacted private dataset and its models under the store's job directory. Protect those files like the recordings themselves.

Activation verifies the registered model bytes and matching qualification. The original context-version-1 models use the unchanged sealed original audit. Live-context models require their own trusted scoped followup qualification, including source, selected data, model hashes, metrics and evaluator seal. An ordinary HTTP caller cannot mint that attestation. A stale or failed audit, missing evaluator key or changed model is rejected.

The portable V4 operation prepares exact selected bytes and a public origin record, runs a new local qualification on the same exposed cases, then installs into an explicitly chosen stopped data directory. Installation alone does not change the active selector; the separate `activate` command or authenticated console action selects one. Existing tasks retain their pinned model when the active selection changes or rolls back. This process does not establish new unseen-case generalization or general desktop learning. See the local requalification instructions in [docs/RUNNING.md](docs/RUNNING.md).

Training provenance is a separate record. The public origin must match one of three existing reviewed audit tuples and the unchanged selection, protocol, all 22 selected artifacts and six original source files. The fresh audit binds those local evidence bytes without substituting them for current executable source. It still requires the full current source, metrics, seal and cleanup checks. Historical Python files are never executed. [ADR 0006](docs/adr/0006-training-origin-and-deployment-qualification.md) records the decision.

## Workspace and research permissions

PermissionedTools receives a trusted grant for a root, allowed origins and operation permissions. Models cannot supply or widen that grant. Workspace permissions require `exclusiveRoot: true`. The embedding application must own that directory and exclude writers that do not use its root lease. The service grants only its private per-configuration directory under the Store. Do not grant a shared user directory while editors, sync tools or other programs can rename its entries.

Cooperating operations serialize through a root lease file. A foreign or stale lease stops access and requires inspection. Paths must remain relative and inside the original real root. The tools reject protected paths, symbolic links, hard links and replaced root directories. Reads compare the opened file identity with the authorized path before and after reading, and reject file changes during the read. Linux also checks the opened descriptor path. Output replacement requires the expected existing hash under the same lease. These checks are application authorization. They are not an OS sandbox against a noncooperating process with the same filesystem permissions. Files and downloads have byte and deadline bounds, and receipts and provenance persist through the caller's Store.

Research reads use only granted public HTTP origins. They reject credentials, secret-bearing query/fragment input, private-address DNS results and unsafe redirects. The controlled loopback test exception requires an explicit trusted grant and is not enabled by the public artifact task route. No arbitrary shell, executable, upload or message operation is available.

Artifact tasks freeze source, output and handwritten JSON/CSV criteria before model generation. A trusted verifier derives every expected value and row from the authorized source bytes. The model receives the functional diff for bounded repair but cannot change the criteria, grant or verifier. Uncertain writes never automatically replay.

## Export and retention

`exportDataset(store)` defaults to sharing redaction. It removes private text and credentials from supported fields, aliases metadata identities and field names consistently within that export, masks labels and replaces original images with a blank placeholder. Original image and demonstration hashes remain inspectable provenance. The random alias salt changes between exports. This bundle is not verified training evidence.

`exportDataset(store, {unredacted:true})` is an explicit private-data opt-in for local training and trusted exact-roundtrip tests. The supervised local learner uses that path within its private store. Imported bundle assertions never become positive labels merely because a hash matches. Ordinary dataset HTTP export uses the redacted default.

`previewRetention(store, cutoff)` lists old unreferenced content-hashed artifacts. The cutoff must be at least one day old. `applyRetention(store, plan, plan.digest)` requires the exact confirmed preview and rechecks references and file identities. It preserves artifacts referenced by runs, events or other state, including active tasks and sealed evidence. Confirmed intention and per-item progress survive process interruption. Missing files count as previously removed only under that persisted intention. Retention is explicit library functionality, not an automatic background deletion job or a general purge of task history.

There is no retention schedule, console deletion control or HTTP retention route. The library caller must request and confirm a plan. Dataset export does not delete local recordings, screenshots or private job datasets.

## Controlled publication and external runners

Controlled causal drafts carry a durable candidate marker. Generic publication cannot bypass their approval by deleting the inference. Registry binds source/fixture/protocol bytes, candidate hash, sealed journals, heldout positives and false-condition no-action guards. The HTTP caller cannot mint trusted evaluator approval.

The benchmark bridge starts one configured local coordinator with `shell=False`. It withholds reward, task configuration and evaluator state, binds returned actions to host/session/run/deadline, and accepts DONE only from verified runtime completion. Its next observation is a runner-roundtrip acknowledgment, not proof of the app effect. Transport loss and takeover preserve uncertainty until the benchmark environment is explicitly reset. The real benchmark VM and external host integrations still need separate execution evidence.
